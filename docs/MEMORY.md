## User Preferences

- Always explain things alongside clickable code links (`[file.py:42](path/to/file.py#L42)`), not prose-only — every explanation of code/bugs/behavior should point at the actual lines.
- Never revert/alter code user manually edited. User change back = final. Don't touch those lines unless asked.
- Never `select_for_update()`; ordinary ORM querysets, no row locks.
- Never create Django migration files manually, never run `makemigrations`. User owns migrations.
- Always `<uuid:pk>/` for UUID detail URL path params.
- No function return/output type annotations unless user asks.
- Prefer explicit `BaseModelSerializer` + `Meta.model` + declared fields over `to_representation()` delegating to another serializer.
- Keep related-object fields nested; don't flatten to top level.
- Don't repeat explicit `read_only=True` fields in `Meta.read_only_fields`.
- Never put derived service-document module-category properties or display methods on the model; serializers compute code and label from `ServiceResult.document_type`.
- "update collection" / "update bruno" → update `bruno/` (requests, folders, envs).
- API collection source of truth is Bruno at `bruno/`. Envs: `bruno/environments/{Development,Production}.bru`. Folder vars omitted so they cannot shadow env tokens.
- **Bruno auth token (2026-09-04):** 401 `"Authorization header must contain two space-delimited values"` = empty Bearer (not Django). Empty runtime `access_token` masks env. `GET List Center Services V2`: `auth: none` + pre-request `req.setHeader('Authorization', 'Bearer ' + env/collection token)`. Login Phone Direct: `bru.deleteVar('access_token')` before set. Associates same symptom if token empty — re-login. Never send empty optional query keys — `~param:`.
- **Always add or update Bruno** (2026-08-26): API add/change → update `bruno/` same change. Never miss.
- **List active filter query param** (2026-08-27): `active=0|1` on list endpoints. Model/DB/body/response field stays `is_active`. Never `is_active` as query param name.
- **Center associate list `role` (2026-09-03):** `GET /centers/<uuid>/associates/?role=0|1`. `1` = role FK set and `AssociateRole.is_active`. `0` = role null or inactive role. Omit / junk = no role filter. User `active=` stays separate. Not `role_type`. Bruno: `bruno/centers/GET List Center Associates.bru`.
- **Center resource list GET omit active** (2026-08-28): associates + v2 room-types / equipment-types / rooms / equipment / services list omit `active` → both. `active=0|1` still filters. Availability lists default-active-only.
- **Bruno optional UUID list filters (2026-09-03):** Do not send empty UUID query params (`room_type_id=`). Disable with `~room_type_id: {{room_type_id}}`. Blank/omit = no filter. Junk UUID on rooms list → 400 `"Invalid room_type_id."` (was uncaught ORM ValidationError 500).
- **Rooms list `type_active` (2026-09-03):** `GET /centers/<uuid>/v2/rooms/?type_active=0|1`. `1` = `room_type_ref` set and `RoomType.is_active`. `0` = type null or inactive type. Omit / junk = no type-active filter. Room `active=` stays separate. Same dict-dispatch as associates `role`. Bruno: `bruno/centers/v2/rooms/GET List Rooms.bru`.
- **Equipment list `type_active` + `room_allotted` (2026-09-03):** `GET /centers/<uuid>/v2/equipments/?type_active=0|1&room_allotted=0|1`. Independent AND filters. `type_active=1` = `equipment_type` set and `EquipmentType.is_active`. `type_active=0` = type null or inactive type. `room_allotted=1` = `room` set and `Room.is_active`. `room_allotted=0` = room null or inactive room. Omit / junk = no that filter. Equipment `active=` stays separate. Same dict-dispatch as rooms `type_active`. Bruno: `bruno/centers/v2/equipments/GET List Equipments.bru`.
- **Success JSON envelope (2026-09-02, mandatory):** Always `{detail, data}` via `send_response` / `response_format` / `Base*APIView` wrap. `data` = object, list, or omit. Never a top-level array. Never nest another `{detail, data}` inside `data`. Never raw `Response(payload)`. List creates (recurring blocks, roster upsert): `data` is the array; client uses `data[0].id`. No `success` key on this envelope (`success` = pre-consult only). Custom list-create: override `post()` and `send_response(..., status=201)`. Do **not** call `send_response` inside `create()` on `BaseListCreateAPIView` — parent `post()` already wraps → nested envelope.
- Always give clickable markdown code links (`[file.py:42](path/to/file.py#L42)`) whenever referencing code, in every response, not just the first mention — user explicitly called this out as a repeated miss (2026-09-04).

**Google Calendar sync: fixed shared organizer, best-effort, commit-after ordering** — Every appointment's Google Calendar event is created/updated/deleted on one fixed, shared account (`settings.GOOGLE_CALENDAR_ID`), not whichever associate is assigned. `get_fixed_calendar_organizer()` (`integrations/google_calendar/google_sync.py`) resolves it via `Associate.google_email__iexact == GOOGLE_CALENDAR_ID`, `Associate.is_active`, **and** a live `google_refresh_token` — checking the refresh token (not just email) matters because disconnect deliberately leaves `google_email` in place as history. Sync is best-effort across all three flows (book/reschedule/cancel, `appointments/serializers/booking.py`): a Google API failure or a disconnected organizer never blocks or fails the appointment operation. `GOOGLE_SYNC_ERRORS` = `(requests.RequestException, ValueError, InvalidToken, ImproperlyConfigured)` — deliberately excludes `KeyError`/`TypeError` so a real bug in our own code (e.g. a malformed event dict) still crashes loudly instead of being silently treated as "Google failed." Rescheduling an appointment away from virtual modality clears any existing Meet link (`patch_event(..., clear_meet_link=True)`) instead of leaving a stale one on the Google event; `extract_meet_link()` checks the event's top-level `hangoutLink` before falling back to `conferenceData.entryPoints`. In each flow, the DB write happens first inside `transaction.atomic()`; the Google call itself is registered via `transaction.on_commit(...)` (through a module-level `sync_*_appointment_and_save()` wrapper — no nested functions) so it only fires once that transaction has actually committed, and the `google_event_id`/`google_meet_link` follow-up save happens in that same callback. This means the DB connection is never held open for the Google HTTP round trip, and a Google-side effect (e.g. deleting the calendar event on cancel) can never land before the DB write it depends on (e.g. the audit log) has durably committed — a rejected booking/reschedule/cancel (overlap, idempotency conflict) never touches Google Calendar. Book's event title is the fixed string `"Appointment Confirmed"`; reschedule's is the fixed string `"Appointment Rescheduled"` — neither includes the service name or appointment code.

## Conventions Established Through Collaboration

**Naming (2026-05-11)** — No abbreviations (`count` not `cnt`, `assignment` not `asg`). Explicit brief formal names. In `CODING_RULES.md` §1.

**Django FK (2026-05-18)** — Never `<field>_id`; always relation `.pk`. In `CODING_RULES.md` §11.

**ORM lookups (2026-07-27)** — `filter(...).first()` in serializers/utils. No `.get()`; handle missing explicitly.

**Serializer add/remove (2026-08-04)** — Write-only `{id}` lists; pop w/ `[]` fallback; helper validates IDs vs parent scope (one query + set diff), raises on field, bulk `add()`/`remove()`. `create()`/`update()`: save → remove before add → refresh counts → return. No dup validation in create/update.

**View querysets (2026-07-27)** — `*ViewMeta` + `filter_kwargs = {}` on `BaseGenericAPIView`; no standalone queryset utils; no `http_method_names`. Serializers never import ViewMeta querysets; resolve models themselves. `utils/db.py` = mutations only (counts/inc/dec/cancel). Representation uses prefetched `to_attr`; no per-object related queries.

**Success envelope (2026-09-02)** — Mandatory `{detail, data}`. See User Preferences. P1 if new endpoint returns a top-level array or nested envelope.

**Serializer and Route Ownership (2026-08-10)** — Serializer `create()`/`update()` own persistence. Views pass context to `serializer.save(...)`; must not capture return, assign `serializer.instance`, or reload for write-response. Route getters take no id args; resolve `self.kwargs["pk"]` via `get_object_or_404`. Shared `*ViewMeta` only if `pk` same resource type. Canonical `<uuid:pk>`. Service docs delete via `/programs/program-result-documents/<uuid:pk>/`; parent result from resolved document. Create response needing nested prefetch: reload via ViewMeta queryset → `serializer.instance`.
